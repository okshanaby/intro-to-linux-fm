## 1. SSH & Secondary Machine

**Multipass** runs a small Ubuntu VM on your computer so you can practice on a second Linux system without extra hardware. Install it from your distro's packages or [multipass.run](https://multipass.run/).<br>

`multipass launch` - Download the default image and start a VM.<br>

`multipass launch --name <vm-name>` - Create a VM with a specific name.<br>

`multipass shell <vm-name>` - Open an interactive shell inside that VM.<br>

`sudo useradd -s <shell> -m -g <group> <username>` - Create a user with login shell `<shell>`, a home directory (`-m`), primary group `<group>`, and username `<username>`.<br>

`sudo useradd -s /bin/bash -m -g ubuntu okshan` - Example: user `okshan`, primary group `ubuntu`, shell `bash`, with a home directory.<br>

`sudo passwd <username>` - Set or change the password for that user.<br>

## 2. Linking two machines with SSH

**SSH** (Secure Shell) lets you open a shell on another machine over the network. You prove who you are with a **key pair**: you keep the **private** key secret on your machine, and you install the matching **public** key on the remote machine in `~/.ssh/authorized_keys`. After that, `ssh` can log in without typing a password (depending on server settings).<br>

### Primary machine (create keys)

`ssh-keygen -t rsa` - Create an RSA key pair. By default this writes the private key to `~/.ssh/id_rsa` and the public key to `~/.ssh/id_rsa.pub`.<br>

`chmod 700 ~/.ssh` - Restrict the `.ssh` directory to your user only (`rwx------`).<br>

`chmod 600 ~/.ssh/id_rsa` - Keep the private key readable only by you.<br>

`chmod 644 ~/.ssh/id_rsa.pub` - Public key can be world-readable.<br>

### Secondary machine (trust the public key)

Copy the **contents** of the primary machine's `~/.ssh/id_rsa.pub` into `~/.ssh/authorized_keys` on the secondary machine (create `~/.ssh` and the file if needed). One line per key.<br>

`chmod 700 ~/.ssh` - Same as on the primary: only your user should access this directory.<br>

`chmod 600 ~/.ssh/authorized_keys` - Only your user should be able to change who is allowed to log in.<br>

### Connect

`ip addr` or `ifconfig` - Show network interfaces and addresses; note the IP you will use for the other host.<br>

`ssh <username>@<ipaddress>` - Connect to the other machine's shell. The first time, accept the host key when prompted (type `yes`).<br>

To log in **both** directions, repeat the flow in reverse: generate or reuse a key on the second machine, append its **public** key to `authorized_keys` on the first.<br>

**Several clients, one server:** append each client's **public** key to `authorized_keys`, **one key per line**, so more than one machine can log into the same account.<br>

## 3. SFTP

**SFTP** (SSH File Transfer Protocol) transfers files over the same SSH connection you use for shells. If SSH works, SFTP is usually available without extra setup. The `sftp` program gives you an interactive session with **local** and **remote** paths at once.<br>

`sftp <username>@<ipaddress>` - Open an SFTP session to the other machine.<br>

`pwd` - Print the **remote** working directory.<br>

`lpwd` - Print the **local** working directory.<br>

`ls` - List files and directories on the **remote** machine.<br>

`lls` - List files and directories on the **local** machine.<br>

`cd` - Change directory on the **remote** machine.<br>

`lcd` - Change directory on the **local** machine.<br>

`get <filename>` - Download a file from remote to local.<br>

`put <filename>` - Upload a file from local to remote.<br>

`!<command>` - Run `<command>` in a local shell (escape from the SFTP prompt temporarily).<br>

## 4. Wget

**GNU Wget** is a command-line tool for downloading files over HTTP, HTTPS, and FTP.<br>

`wget https://example.com/file.zip` - Download `file.zip` into the current directory (default filename from the URL).<br>

`wget -O myfile.zip https://example.com/file.zip` - Download and save as `myfile.zip` instead of the URL's basename.<br>

`wget -P /home/user/downloads https://example.com/file.zip` - Use `-P` as the **directory prefix**: save the file under `/home/user/downloads`.<br>

`wget -c https://example.com/file.zip` - **Continue** a partial download (resume) if the server supports it.<br>

`wget -r https://example.com/` - **Recursive** fetch (follows links; use carefully—large sites and server policies apply).<br>

`wget --limit-rate=200k https://example.com/file.zip` - Cap download speed (here, 200 KiB/s).<br>

`wget -i links.txt` - Read URLs from `links.txt`, **one URL per line**, and download each.<br>

## 5. Curl

**curl** sends and receives data over URLs (HTTP/HTTPS and more). Use it for quick downloads, inspecting responses, and calling HTTP APIs.<br>

`curl https://example.com` - Print the response body in the terminal (nothing is saved to disk unless you add `-o` or `-O`).<br>

`curl -o page.html https://example.com` - Save the response body to `page.html`.<br>

`curl -v https://example.com` - **Verbose**: show DNS, TLS handshake, request/response headers, and the status line.<br>

`curl https://api.github.com` - Example **GET**; without `-X`, the method is **GET**.<br>

`curl -X POST https://example.com/api -d "name=okshan&age=20"` - **POST** form-style data (curl sets a suitable default `Content-Type` for `-d`).<br>

`curl -X POST https://example.com/api -H "Content-Type: application/json" -d '{"name":"okshan","role":"dev"}'` - **POST** JSON; the `Content-Type` header should match the body.<br>

`curl -H "Authorization: Bearer YOUR_TOKEN" https://api.example.com/user` - Send a custom header (typical for API tokens).<br>

`curl -o /dev/null -s -w "Time: %{time_total}\n" https://example.com` - Discard the download (`-o /dev/null`), stay quiet (`-s`), print total time in seconds (`-w`).<br>
