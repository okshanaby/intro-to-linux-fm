## 1. Writing shell scripts

A **shell script** is a text file that contains shell commands.

`vi gen_files.sh` - Create or edit the script file (you can use any editor you like).<br>

`chmod +x gen_files.sh` - Give the script executable permission.<br>

`bash gen_files.sh` - Run the script in a **new** Bash process. When it finishes, your current shell is unchanged, so a `cd` inside the script does not move your interactive session.<br>

`source gen_files.sh` or `. gen_files.sh` - Run the script **in the current shell**. Variables, functions, and `cd` from the script affect your current session.<br>

### Example

**`gen_files.sh`:**

```sh
mkdir -p ~/temp
cd ~/temp
touch file{1..10}.txt
echo done
```

`bash gen_files.sh` - Ensures `~/temp` exists, changes into it, creates `file1.txt` through `file10.txt`, and prints `done`.<br>

## 2. Hashbang or Shebang

A **shebang** is the first line of an executable script. It tells the system which interpreter should run the file. The script does **not** need a special file extension; what matters is the shebang and executable permission.<br>

`vi <script-name>` - Create the script file.<br>

`#!<interpreter-path>` - Put this on the first line to choose the interpreter, for example `#!/bin/bash` or `#!/usr/bin/node`.<br>

`chmod +x <script-name>` - Give the script executable permission.<br>

`./<script-name>` - Run the script directly.<br>

### Example: running a Node.js script

`which node` - Show the path to the Node.js executable so you can use it in the shebang.<br>

**`node_test`:**

```js
#!/usr/bin/node
console.log("Running nodejs script");
```

`chmod +x node_test` - Make the file executable.<br>

`./node_test` - Run the script; it prints `Running nodejs script`.<br>

## 3. PATH and variables

### PATH

If a script is in a directory listed in your `PATH`, you can run it by name from anywhere instead of typing `./script-name`.<br>

`mkdir -p ~/my_bin` - Create a directory for your personal scripts.<br>

`mv script1 script2 ~/my_bin/` - Move scripts into that directory.<br>

`vi ~/.bashrc` - Open your Bash config file.<br>

Add this line:

```sh
export PATH=~/my_bin:$PATH #appends the current PATH variable to include our script executables
OR
export PATH="$HOME/my_bin:$PATH"
```

`source ~/.bashrc` - Reload the Bash config so the updated `PATH` takes effect in the current shell.<br>

`node_test` - If `node_test` is in `~/my_bin` and has executable permission, you can now run it from anywhere by name.<br>

### Variables

Shell variables let you store values and reuse them in commands. This makes scripts easier to read and update.<br>

**`gen_files.sh`:**

```sh
# Store the target directory in a variable.
DESTINATION="$HOME/temp"

mkdir -p "$DESTINATION"
cd "$DESTINATION"
touch file{1..10}.txt
echo done
```

`DESTINATION="$HOME/temp"` - Store the path in a variable. Using `$HOME` is safer here than `"~/temp"` because `~` does not expand inside quotes.<br>

`"$DESTINATION"` - Quote variable expansions when they might contain spaces or special characters.<br>
