## 1. `cron`

`cron` is a Linux service that runs commands or scripts on a schedule.

This section builds on `8. Shell Scripts.md`: cron jobs usually run shell scripts, so the same basics still matter:

- use a proper shebang such as `#!/bin/bash`
- make the script executable with `chmod +x`
- prefer absolute paths or `$HOME/...`
- quote variables like `"$DESTINATION"`

### Cron folders

Scripts placed in these system cron directories run automatically on their matching schedule:

`/etc/cron.hourly` - Run once every hour.<br>
`/etc/cron.daily` - Run once every day.<br>
`/etc/cron.weekly` - Run once every week.<br>
`/etc/cron.monthly` - Run once every month.<br>

`sudo chmod +x <file>` - Make sure the script is executable before placing it in a cron folder.<br>

### Example

`vi affirmation` - Create the script file.<br>

**`affirmation`:**

```sh
#!/bin/bash

DESTINATION="$HOME/temp-files"

mkdir -p "$DESTINATION"

# Fetch an affirmation and append it to a log file.
AFFIRMATION=$(curl -s https://www.affirmations.dev/ | jq -r '.affirmation')
echo "- $(date): $AFFIRMATION" >> "$DESTINATION/affirmation-logs"
```

`chmod +x affirmation` - Make the script executable.<br>

`sudo cp "$HOME/my_bin/affirmation" /etc/cron.hourly/` - Copy the script into the hourly cron folder so it runs automatically.<br>

## 2. `crontab`

`crontab` lets you define your own custom schedules instead of only using the preset hourly/daily/weekly/monthly folders.

`crontab -e` - Open the current user's crontab file for editing.<br>
`crontab -u ubuntu -e` - Edit the crontab for user `ubuntu`.<br>
`sudo crontab -u root -e` - Edit the root user's crontab.<br>

### Format

A crontab entry has five time fields followed by the command or script:

```sh
* * * * * <command-or-script>
```

The five fields mean:

`first *` - minute (`0-59`)<br>
`second *` - hour (`0-23`)<br>
`third *` - day of month (`1-31`)<br>
`fourth *` - month (`1-12`)<br>
`fifth *` - day of week (`0-7`, where `0` and `7` are Sunday)<br>

### Example

```sh
*/2 * * * * "$HOME/my_bin/affirmation"
```

This runs the `affirmation` script every 2 minutes.

### Good practice

Cron runs in a limited, non-interactive environment, so jobs are more reliable when you:

- use full paths to scripts and commands
- keep scripts executable
- reuse the shell scripting habits from `8. Shell Scripts.md`
