## 1. Environments

`printenv` - List all environment variables in the current shell.<br>

`echo $USER` - Print the value of the `USER` variable.<br>

`USER='someone'` - Set or change a variable for the **current** shell session only (not saved after you close the terminal).<br>

`sudo vi /etc/environment` - Edit system-wide defaults that apply at login. Changes take effect on the **next** login (or new session, depending on how your distro reads this file).<br>

### `.bashrc`

Runs for **non-login** interactive shells.<br>

**Typical cases:**<br>

- Opening a new terminal tab or window in a desktop environment
- Starting a nested shell from an existing shell
- `su username` (without `-`)

**Common contents:**<br>

- Aliases and shell functions
- Prompt (`PS1`) and small interactive settings

`vi ~/.bashrc` - Edit your user's `bashrc` (no `sudo` needed in your home directory).<br>

`export VARIABLE_NAME=value` - Define a variable and **export** it so child processes inherit it.<br>

`source ~/.bashrc` - Reload `~/.bashrc` in the current shell without opening a new terminal.<br>

### `.bash_profile`

Runs for **login** shells.<br>

**Typical cases:**<br>

- `su - username`
- SSH login
- Console login on a TTY (e.g. Ctrl+Alt+F2)

**Common contents:**<br>

- Environment variables you want on every login
- Programs or setup that should run once per login

`vi ~/.bash_profile` - Create or edit this file in your home directory.<br>

Many setups **source** `~/.bashrc` from `~/.bash_profile` so login shells get the same interactive config. If yours does not, add:<br>

```bash
if [ -f ~/.bashrc ]; then
  . ~/.bashrc
fi
```

## 2. Processes and jobs

`ps` - List processes. Common forms: `ps`, `ps aux` (all users, more columns).<br>

`kill <pid>` - Ask the process to exit; sends `SIGTERM` (15).<br>

`kill -9 <pid>` - Force termination if the process ignores `SIGTERM`; sends `SIGKILL` (9).<br>

`kill -STOP <pid>` - Pause the process; sends `SIGSTOP`.<br>

`kill -CONT <pid>` - Resume a stopped process; sends `SIGCONT`.<br>

A **job** is a process (or pipeline) the shell is managing for you, usually because you started it in that terminal.

`jobs` - List jobs for this shell (running, background, and suspended).<br>

`<command> &` - Run `command` in the background; you keep the shell prompt.<br>

**Foreground** - The job owns the terminal until it finishes or you suspend it. Example: `sleep 100` blocks further typing in that shell.<br>

**Background** - The job runs without blocking the prompt. Example: `sleep 100 &`.<br>

`Ctrl + z` - Suspend the foreground job; it becomes a stopped job (not killed). You can resume it with `fg` or `bg`.<br>

`bg %<n>` - Continue a stopped job in the background (`<n>` is the job number from `jobs`).<br>

`fg %<n>` - Bring job `<n>` to the foreground.<br>

`kill %<n>` - Send a signal to job `<n>` (same `kill` as with a PID).<br>

## 3. Exit codes and shell operators

`echo $?` - Print the exit code of the last command (in `bash`, `0` means success; any non-zero value means failure).<br>

**Common exit codes:**<br>

- `0` - Success.
- `1` - General error (many programs use this as a catch-all).
- `2` - Misuse of a shell builtin or invalid arguments (common with `bash`).
- `126` - Command found but not executable (permissions or not a binary/script).
- `127` - Command not found.
- `128` - Invalid argument to `exit` (in some shells).
- `130` - Script or command ended by `SIGINT` (often **Ctrl + c**); conventionally `128 + 2`.
- `137` - Process killed by `SIGKILL` (often `128 + 9`; e.g. OOM killer or `kill -9`).
- `255` - Exit status out of range, or some programs use it for failure when wrapping other codes.

`<command1> && <command2>` - Run `<command2>` only if `<command1>` succeeds (exit code `0`).<br>

`<command1> || <command2>` - Run `<command2>` only if `<command1>` fails (non-zero exit).<br>

`<command1> ; <command2>` - Run both in order; the second runs regardless of the first command’s exit code.<br>

## 4. Subcommands

`$(<command>)` - Run `<command>` and substitute its standard output into the surrounding text (the shell strips one trailing newline from the result).<br>

`echo "Hi, I think $(whoami) is a cool user"` - The shell runs `whoami` first, inserts the username into the string, then runs `echo` with the final text.<br>
